# EveryEveningBot

Обычный Telegram-бот для работы с 10-м и 11-м Шагами. Без Mini App.

## Статус ветки проверки

Это подготовленный пакет дополнений, **не обновление действующего production**. Приём реальных отчётов в main не менялся. См. `docs/AUDIT-2026-09-19.md`: там явно перечислены исправления, ограничения и блокирующие пункты до выпуска.

Добавлены молитвы и ориентиры по БК, личная история `/history`, карточка подключённого подопечного, `/resume`, корректная отмена и выбор задания. Длинные сообщения разбиваются. Время и timezone можно сохранить, но автоматический планировщик этой веткой не подключается.

Молитвы — адаптации для личного пользования. Раздел БК — краткие ориентиры и вопросы, не полный текст книги и не официальное издание АА.

## Тестирование без секретов

```bash
python -m compileall -q api eveningbot tests
python -m unittest discover -s tests -v
```

Тесты не подключаются к Telegram и Redis. Весь ввод — вымышленные записи.

## Настройка перед согласованным выпуском

Исходные переменные: `BOT_TOKEN`, `OWNER_TELEGRAM_ID`, `DEFAULT_TIMEZONE`, `KV_REST_API_URL` / `KV_REST_API_TOKEN` либо `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`.

Новые обязательные переменные production: `WEBHOOK_SECRET` и `PUBLIC_BASE_URL`.

Сгенерировать секрет локально:

```bash
python -c 'import secrets; print(secrets.token_urlsafe(32))'
```

Секрет хранится в Vercel, не в GitHub, не в сообщениях боту. PUBLIC_BASE_URL — постоянный адрес без `/api/index`, query и fragment. В Preview обработчик POST запрещён независимо от наличия секретов: безопасное тестирование не использует рабочую БД.

После согласованного deployment установите переменные локально в защищённом окружении и выполните:

```bash
python scripts/configure_webhook.py
```

Скрипту нужны только `WEBHOOK_SECRET` и `PUBLIC_BASE_URL`; BOT_TOKEN он не читает. GET `?setup=1` больше не меняет webhook. Настройка выполняется авторизованным POST. Без согласованной установки секрета на стороне Telegram выпуск нельзя считать завершённым.

Формат и ключи существующих отчётов сохранены. Автоматические получатели старой модели одного спонсора не менялись. Новый просмотр чужой истории разрешён только владельцу бота и только для явно подключённого подопечного. Миграция Redis и удаление реальных данных не выполняются.
